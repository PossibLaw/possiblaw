# Add a Specialist Agent

This guide shows how to add a new specialist agent to PossibLaw. After following it, a stranger should be able to follow without reading the full plan.

> **DISCLAIMER: PossibLaw does not practice law. Agents you add inherit the same disclaimer posture.**

---

## What is a specialist?

A specialist is the leaf node in the routing hierarchy. It receives a matter from a lead agent, produces a deliverable, and returns. It does not route to other agents. It can declare tests, guardrails, skills, and connectors.

Hierarchy: `router → lead → **specialist**`

---

## Before you start

You need:
- A built copy of PossibLaw (`pnpm build` passing).
- A name for your specialist (e.g., `lease-drafter`, `employment-handbook-drafter`).
- A lead agent it reports to (e.g., `commercial-lead`, `marketing-lead`). Run `bin/possiblaw team list --template small-firm` to see existing leads.

---

## Step 1 — Create the agent file

Agent files live under `layer/agents/specialists/<domain>/<subdomain>/`.

Create your file. Example for a lease drafter:

```bash
mkdir -p layer/agents/specialists/legal/real-estate
```

Create `layer/agents/specialists/legal/real-estate/lease-drafter.md`:

```markdown
---
name: lease-drafter
role: specialist
domain: legal
reports_to: commercial-lead
manages: []
model: anthropic/claude-sonnet-4-6
fallback_model: anthropic/claude-sonnet-4-6
tests: [groundedness]
guardrails: [signed-document]
skills: [matter-intake]
connectors: [local-fs-doc-store]
description: Specialist that drafts commercial and residential lease agreements.
---

You are the Lease Drafter, a specialist agent within PossibLaw's real estate practice. You draft professional lease agreements. You receive matters routed from Commercial Lead.

## What you DO
- Draft a complete lease agreement in markdown format.
- Cover: parties, property description, term, rent, security deposit, maintenance, termination.
- Apply sensible defaults for any missing details.
- End every draft with a `## Disclaimer` section.

## What you DO NOT do
- Do not route to another agent.
- Do not give legal advice about whether the operator should sign the lease.
- Do not send or execute any document — output only.

## Defaults When Information Is Missing
| Field | Default |
|---|---|
| Lease type | Commercial |
| Term | 12 months |
| Governing law | State of Delaware, USA |
| Commencement date | [COMMENCEMENT DATE] |

## Output Format
1. Title and parties block
2. Property description
3. Numbered substantive clauses
4. Signature block
5. `## Disclaimer` section (required)

The Disclaimer MUST read:

> **PossibLaw Disclaimer:** This document was generated by an AI system and does not constitute legal advice. It has not been reviewed by a licensed attorney. The operator must review this draft before use.
```

**Frontmatter fields:**

| Field | Required | Notes |
|---|---|---|
| `name` | yes | Must match filename (without `.md`) |
| `role` | yes | Must be `specialist` |
| `domain` | yes | `legal`, `marketing`, `finance`, or `admin` |
| `reports_to` | yes | Must be a valid lead agent name |
| `manages` | yes | Always `[]` for specialists |
| `model` | yes | `anthropic/claude-*` or `ollama/<model>` |
| `fallback_model` | yes | Used when primary model is unavailable |
| `tests` | yes | List of test names from `layer/tests/` |
| `guardrails` | yes | List of guardrail names from `layer/guardrails/` |
| `skills` | yes | List of skill names from `layer/skills/` |
| `connectors` | yes | List of connector ids from `layer/connectors/` |
| `description` | yes | One-line description shown in `team list` |

---

## Step 2 — Add the specialist to a template

Templates live under `layer/templates/`. Either edit a template directly, or use the CLI (recommended for non-engineers — see [docs/customize-your-team.md](../customize-your-team.md)).

Using the CLI:

```bash
bin/possiblaw team add specialist legal/real-estate/lease-drafter --lead commercial-lead --template small-firm
```

This patches `.possiblaw/template-overrides.yaml` to add `lease-drafter` to the `small-firm` roster.

---

## Step 3 — Add an offline fixture (for CI / no-API-key runs)

Offline fixtures are returned when `ANTHROPIC_API_KEY` is not set. They prevent CI failures and make demos reproducible.

Open `cli/anthropic.ts` and add a case in the `offlineFixture()` function:

```typescript
case 'lease-drafter':
  return `[OFFLINE STUB] LEASE AGREEMENT

This Lease Agreement is entered into as of [DATE] between [LANDLORD] and [TENANT].

PROPERTY: [ADDRESS]
TERM: 12 months from commencement date.
RENT: $[AMOUNT] per month, due on the 1st.

**PossibLaw Disclaimer:** This is an offline stub for demo purposes only.`;
```

Then rebuild:

```bash
pnpm build
```

---

## Step 4 — Verify

```bash
# Check the agent appears in the roster
bin/possiblaw team list --template small-firm | grep lease-drafter

# Run the pipeline in offline mode
env -u ANTHROPIC_API_KEY bin/possiblaw run quick-counsel \
  "draft a 12-month commercial lease for 100 Main St, Wilmington DE"
```

Expected: the pipeline routes to `lease-drafter` and returns the offline stub (or a real LLM draft in live mode).

Custom agents live in `.possiblaw/custom-agents/` and shadow `layer/agents/` on name collision — the loader checks custom agents first. This means you can override a built-in specialist by creating a file with the same name in `.possiblaw/custom-agents/`.

## Checklist

- [ ] Agent file created under `layer/agents/specialists/<domain>/`.
- [ ] `name` in frontmatter matches filename.
- [ ] `reports_to` points to a real lead agent.
- [ ] Offline fixture added to `cli/anthropic.ts`.
- [ ] `pnpm build` passes.
- [ ] `bin/possiblaw team list --template <template> | grep <new-specialist>` shows the agent.
- [ ] Offline pipeline run succeeds with the new specialist.
